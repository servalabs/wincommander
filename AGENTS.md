## Project shape

- **Stack:** Tauri v2 desktop app. Rust backend (`src-tauri/`), React 19 + TypeScript 6 + shadcn/ui (Radix) + Tailwind 4 frontend (`src/`), AES-256-GCM-encrypted PowerShell 5/7 modules, optional Python 3.12 for local AI. Bun is the package manager / runner.
- **Executable products:** `wincommander-free.exe` (`commander-free`, AGPL; strings-clean gate enforced), the headless commercial `wincommander-pro.exe` sidecar, and the separately downloaded private `wincommander-investigator.exe` desktop app. Free contains only the Investigator delivery/launch surface; the workflow UI and PDF host live in `../wincommander-pro/investigator-app/`. `wci-verify.exe` remains independently distributable. `wincmd-shared` is the pure-data IPC crate used by the processes. `wincmd-search` (`src-tauri/wincmd-search/`) is the AGPL content-search engine.
- **Fleet crates (permissive, shared across products):** `fleet-proto` (`src-tauri/fleet-proto/`) is the fleet wire-protocol SSOT — wire types + canonical signing preimage builders, pinned by frozen golden-vector tests; changing the byte layout needs a coordinated deploy of every consumer. `fleet-agent-core` (`src-tauri/fleet-agent-core/`) is the generic fleet-client loop (enroll/check-in/verify/dispatch) with a `types`/`transport` feature split — `types` alone (no `reqwest`/`tokio`) is what a Free binary would link to verify a signed command locally. Both are shared with TuxCommander; the wire contract is additionally shared with the Android agent via a golden-vector conformance fixture. See ARCHITECTURE.md for the full description.
- **Fleet server:** standalone axum + sqlx/Postgres self-host server at `../commander-pro/fleet-server/`; builds + unit-tests with NO Postgres via in-memory store impls (`src/store/memory.rs`); Postgres path (`src/store/pg.rs`) is compile-checked + serialised per-org via `pg_advisory_xact_lock`.
- **Windows-only enforcement stance:** The fleet endpoint enforcement engine — `commander-svc` (the SYSTEM service), the reconciler loop, the hard-lock writers, and all pipe/DACL/peer-SID code — is **Windows-only by design**. Non-Windows targets (Linux CI, macOS dev) compile via `#[cfg(not(windows))]` no-op stubs that satisfy the type checker but do nothing at runtime. This is intentional: we do **not** invest in a cross-platform enforcement trait abstraction. Do not introduce a trait that promises enforcement semantics on non-Windows platforms; the stubs exist solely so the workspace compiles in CI.
- **Entry points:** `src/main.tsx` / `src/App.tsx` (frontend); `src-tauri/commander-free/src/main.rs` → `lib.rs::run` (Tauri builder + command registration); `src-tauri/commander-free/src/backend.rs` (`run_backend_script` dispatcher).

## Working here

All commands run from the repo root in PowerShell on Windows 11 (Administrator for most runtime operations).

- **Setup:** first run `powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\dev.ps1` — installs Bun when absent and the exact Rust toolchain from `rust-toolchain.toml`; Visual Studio C++ Build Tools remain a manual prerequisite. Afterwards, `bun install` is sufficient.
- **Run / dev:** `bun run dev:tauri`
  - canonical entry; runs `beforeDevCommand` (verify pinned toolchain → fetch icons → `bun run dev:server`: kill stale dev procs → `encrypt-backend` → build Pro debug → Vite). Use `bun run dev:reset` to erase `%APPDATA%\WinCommander\settings.json` and test first-launch Help & Setup.
- **Build (release):** `bun run build` (salt rotate → Pro release build → `tsc` → `vite build` → bundle).
- **Pro sidecar:** `bun run build:pro` / `build:pro:release` (auto-discovers the sibling Pro workspace; override with `WINCOMMANDER_PRO_WORKSPACE` if your local checkout lives elsewhere).
- **Fleet server:** `cargo test -p fleet-server` (from `../commander-pro/`); no Postgres required — memory store impls handle all tests. Set `DATABASE_URL` to run Postgres integration tests.
- **Portable edition:** build `commander-free` **and** `commander-pro` with `--features portable`. That compiles out the trial and turns on the Pro sidecar's independent licence verification (`entitlement.rs`); both binaries must agree on the feature or the embedded Pro won't enforce.
- **Re-encrypt PS modules:** `bun run encrypt-backend` — **required after any edit to `scripts/**/*.ps1`** (rotates the per-build AES salt; `build.rs` picks it up next `cargo build`).
- **Type-check:** `bun x tsc --noEmit`
- **Lint (frontend):** `bun run lint` (`eslint . --max-warnings=0`) — **blocking CI gate**
- **Lint (Rust):** `cd src-tauri && cargo clippy --workspace --all-targets -- -D warnings` — **blocking CI gate**; toolchain pinned to 1.97.1 (`rust-toolchain.toml`) so local == CI
- **Tier + risk invariants:** `bun run lint:tiers`
- **Regenerate Rust→TS wire types:** `bun run gen:types` — **required after editing the fleet/IPC wire types** in `fleet-proto` (reachable as `wincmd_shared::fleet`) or the IPC envelope in `lib.rs`; rewrites `src/types/generated/*`. CI's `codegen-drift` job (`bun run gen:types:check`) blocks the merge if you forget. `src-tauri/wincmd-shared/bindings/` is gitignored ts-rs scratch — never hand-edit `generated/`
- **Free-binary AV-clean strings gate:** `bun run lint:strings-free` — reads forbidden tokens from `tools/strings-grep-forbidden.txt` (edit there, not the script); runs locally as a **hard gate** (`-HardGate`, exits 1 on any hit); the CI `strings-grep-free` job runs the same scan as a **blocking** gate (no `continue-on-error`), so a forbidden token fails the merge
- **Rust check / test:** `cargo check --all-targets` and `cargo test --workspace` (run inside `src-tauri/`; `cargo test -p wincmd-shared` covers the IPC tests). If rustc blows its thread stack compiling Tauri proc-macros, set `RUST_MIN_STACK=16777216`.
- **CI:** `.github/workflows/invariants.yml` (runs on `pull_request` + `push` to `main`, plus manual `workflow_dispatch`) runs ts-schema, tier-invariants, bun-test, codegen-drift, eslint, cargo-clippy, cargo-check, cargo-test, gitleaks, audit, and `strings-grep-free` as **hard gates**. Only `cargo-deny` remains report-only (`continue-on-error`). `release.yml` builds + signs the MSI. CI uses `--frozen-lockfile`; don't remove it.

## Conventions

- **Known issues:** do not publish internal readiness or remediation ledgers in this repository. Report public-safe defects through the normal issue process.
- **Engineering guardrails (folded from RULES.md):**
  - Mental model: `settings.ideal` = user intent, `settings.current` = machine reality; PowerShell modules reconcile current → ideal.
  - **Feature lifecycle:** (1) update schema in `src/types/settings.ts` + `settings.rs`; (2) add backend PS logic in `scripts/modules/`; (3) `bun run encrypt-backend`; (4) register the command in `lib.rs` and wire through `useBackend`.
  - Strict typing in backend wrappers/hooks; no `any` in `useBackend`/`useSettings` paths. Remove dead/vestigial code. Add concise `// KT: <lesson>` comments for non-obvious fixes.
  - **Search with ripgrep (`rg`)** as the primary code-search tool.
  - Keep new files under ~300 lines; components are pure renderers — business logic goes in `src/hooks/` (state + IPC) or `src/lib/` (pure functions).
- **Styling (single approach per concern):** design tokens / Blueprint overrides in `src/index.css`; global keyframes in `src/index.css` (legacy/global) or `src/styles/v2-theme.css` (the V2 shared micro-animation library); layout via Tailwind utilities; component cosmetics in co-located `.css`; enter/exit animation via Framer Motion `AnimatePresence`. Banned: `<style>` JSX blocks, inline `style={{}}` for layout/color, `onMouseEnter/Leave` for hover (use CSS `:hover`), hardcoded hex/rgba in JSX (use `var(--color-*)`), raw large `z-index` (use `var(--z-*)`), `.bp5-*` prefixes (use `.bp6-*`). **Rounding (updated 2026-06):** minimum **2px** rounding — **nothing sharp**. Use `var(--radius-*)` tokens (`sm` 2px badges/chips · `md` 4px inputs · `lg` 6px buttons/rows · `xl` 8px cards/dialogs · `full` pills); never `border-radius: 0` on a visible box. `font-mono` for data/badges/scores; feedback animations < 300ms. Canonical detail lives in the code: design tokens in `src/index.css` / `src/styles/v2-theme.css`, the shadcn primitives in `src/components/ui/`, and the layering summary in [ARCHITECTURE.md](ARCHITECTURE.md).
  - **V2 frontend (migrating 2026-06):** the app moved off **BlueprintJS** to **shadcn/ui (Radix) + a V2 token system**. V2 tokens live in `src/styles/v2-theme.css` (loaded after `index.css`): default theme **Anduril** (warm-orange dark) + **Daylight** (light), driven by `data-theme` + the `.dark`/`.light` class. The shadcn kit is in `src/components/ui/`; **new code imports primitives from `src/components/ui/*`** (Button, Dialog, Switch, Select, Tabs, Command, sheet, …). `src/components/ui/bp.tsx` is a Blueprint-API-compatible shim that legacy call sites import — don't write new code against it. Icons are **Lucide** via `src/components/ui/icon.tsx` (`<Icon icon="kebab-name" />`). Toasts use **Sonner** (`src/utils/toast.ts`). Radius softened (base 8px, cards 12px). The legacy `.bp6-*` overrides in `index.css` are now dead (Blueprint removed) and slated for deletion. The full V2 migration plan is tracked privately in `commander-pro`.

## Security rules (read before editing Tauri commands, licence code, or capabilities)

These were added in response to real audit findings (tracked privately). Ask before relaxing any.

- **Tauri capabilities** (`src-tauri/commander-free/capabilities/default.json`): don't widen `fs:scope` beyond `$APPDATA/WinCommander/**` + `$RESOURCE/**` + `$TEMP/WinCommander-*`. Don't widen `shell:allow-execute`. New webview labels get their own narrow capability JSON, not the default list.
- **Tauri commands** (`backend.rs`, `lib.rs`): every new **paid** `#[tauri::command]` must get a `get_command_tier` arm (missing = silently free). Every command that loads a PS module must get a `get_module_for_command` arm. **Never** accept a URL/host or an integrity hash from the frontend — pin hosts in Rust (`pro_install.rs::ALLOWED_UPDATE_HOST`) and source hashes from a signed manifest or build-time embed.
- **Licence** (`license.rs`): `WINCMD_LICENSE_PUBLIC_KEY` is `option_env!()`-only in release; runtime override is `#[cfg(debug_assertions)]`-gated — don't restore the runtime override. Don't trust the licence cache without signature verification. `current_device_hash()` is the binding (motherboard UUID + disk serial via `Get-CimInstance`, NOT the removed `wmic`; memoised per process) — don't add paths that skip it.
- **Sidecar** (`sidecar.rs`): verify the Pro binary hash at handshake against the pinned value; keep the per-session pipe + 32-byte token + HMAC on every frame.
- **Frontend** (`src/`): never `dangerouslySetInnerHTML` (enforced by `react/no-danger`). Never call `shell.Command("powershell")` from JS — add a Rust command so the tier gate + module gate + escaping run. The entitlement gate in `useEntitlements.ts` is UI-only; the backend's `require_paid()` is the source of truth.
- **CI / release:** release builds must be `--release` (the dev-only paid bypass is real). Keep `--frozen-lockfile`. Never commit `.env`.

## Gotchas

- After editing any `.ps1`, you **must** run `bun run encrypt-backend` or the change won't be picked up (the binary loads `.enc` blobs, not `.ps1`).
- **es.exe: one query token per argv entry, always (2026-07).** `es.exe` joins its non-flag argv entries with spaces, but a *single* argv entry containing a space is treated as a **quoted phrase** — so passing a whole multi-token query as one argument returns **zero rows with no error**. This shipped broken: `search_everything` passed `&query` as one entry, so the app's own app-priority query (`brave* ext:exe;lnk;msi;appx;msix`) never matched anything and `Brave.lnk` only surfaced by luck from the general query. `backend.rs::tokenize_es_query` now splits (keeping quoted runs intact) and the frontend sends a pre-split `tokens` array; folder scope travels as the `-path` **flag**, never a `path:` token (a `path:` token substring-matches, so scoping to `…\wincommander` leaked results from `…\wincommander-pro`). Corollary: **never "simplify" a token array back into a joined string.** The failure is silent in every direction — no error, no warning, just an empty list that reads as "your file doesn't exist".
- **A leading `-` is a switch, not a search term (2026-07).** `backend.rs::validate_es_tokens` rejects any token starting with `-` or `/` as argv injection, which is correct — but a raw whitespace split turns the very common `"Name - Description"` filename pattern (Windows ships WinX shortcuts like `01a - Windows PowerShell.lnk`) into a lone `-` token, erroring the whole search. Measured: **198 of 4,014 real files (4.9%)** could not be found by typing their own visible name. `searchQueryPlan.ts::toEverythingToken` now wraps every user word in `*…*` and drops punctuation-only words. The wrap is a **no-op** for Everything's default substring matching (verified: `ead` and `*ead*` both return 20,216 rows) while making a leading `-`/`!`/`|`/`<`/`>` impossible — `!` in particular was being parsed as Everything's NOT operator and returned ~1.4M *wrong* rows silently.
- **Never spawn a per-result-row process in `parse_es_output`.** It used to call `get_file_icon_data_sync` per app-like row — one PowerShell each, **measured ~866 ms apiece**, serially, *outside* the search timeout and on a tokio worker thread. Capping it at 12 still meant ~10.4 s of unbounded stall on nearly every keystroke (twice over, since the apps-boost query runs concurrently). It is now removed entirely: the frontend already lazy-fetches icons per *visible* row via `get_file_icon_data` and memoises them (`esbIconCache`), which is strictly better. Any future enrichment here must be inside the timeout, on `spawn_blocking`, and bounded per item.
- **Search ranking can only reorder what was fetched.** Everything's native order is by **path**, which buries the user's own files behind `C:\Windows` and `C:\Program Files`: measured, the developer's own `D:\GitHub\assets` ranked **1193rd of 1239** folders named `assets*`, so a 50-row window never contained it and no client-side sorting could recover it. Hence `dm-descending` as the default sort for *every* query plus a 300-row `MATCH_FETCH` (fetching 300 costs ~0.1–0.5 s; 50 vs 300 differed by 9 ms). If you narrow the window or drop the sort, re-measure recall — and note the recency sort is a *bet* that costs old-but-wanted files, which is why `fetchMatches` merges a second **unsorted** page.
- **Filter client-side only when the backend genuinely cannot filter.** The Search Files panel used to send the bare query, over-fetch 5x, and filter in JS — so "folders named assets" fetched 50 rows and kept the folders among them, reporting **no results** while ~1,200 existed. Filtering after a limit is the same bug class as ranking a too-small window. It also double-filtered wrongly: the client's "last 7 days from local midnight" disagrees with Everything's `dm:thisweek` ("since the start of this week"), discarding rows the backend correctly returned.
- **Search latency benchmarks must run alone.** Everything is a single shared `Everything.exe` daemon with no per-request cancellation, so concurrent load-testing invalidates every timing — and one expensive query (`attrib:` is un-indexed and ran **>100 s** live-scanning the disk) degrades every other search for minutes. A parallel test run produced a false "the Duplicates chip deterministically exceeds the 6 s timeout" finding that drove a feature removal; on a quiet machine `dupe:` is **147–161 ms**. Treat any search timing taken under concurrent load as void.
- **Don't trust Everything's `type:`/`pic:` macros; use explicit `ext:` sets.** `type:picture` returned only `.bmp` files and `type:picture *.png` returned **zero** — it matches shell type *descriptions*, which vary per machine. `FILE_TYPE_EXTENSIONS` in `fileNameSearch.ts` is the deterministic source of truth, and a missing extension there is a silent "your file does not exist" (`.c`/`.h`/`.hpp` alone accounted for ~35,000 invisible files before they were added).
- **PowerShell modules must declare their transitive helpers:** `tweaks/security` calls `Get-WCSetting`, so `backend.rs::get_module_dependencies` must continue to prepend `core/settings-bridge`. Adding a direct script call to a helper from another module requires the same dispatcher dependency treatment plus a regression test; loading only the command's primary module reproduces a runtime `CommandNotFoundException`.
- **External alerts use a separate narrow WebView:** Rust emits `wc-native-notification`; `ExternalNotificationBridge` positions the `notification-alerts` window and forwards `wc-custom-notification` only after its ready handshake. `CustomNotificationWindow` owns visibility and pointer passthrough. Don't restore a second Sonner/Action Center notification for the same event, resize in both windows, or broaden the alert capability beyond the window operations it needs.
- **Windows AI controls are composed, not parallel:** keep `Remove-CopilotAIComponents` as the canonical policy/app-feature toggle in Security & Apps. `Invoke-AIControlOperation` is only for explicit advanced removal, repair, and classic-app actions and must retain a fixed `ValidateSet`; do not add another Windows AI panel or accept raw paths/commands from the frontend. Backups belong under the ACL-restricted `%ProgramData%\WinCommander\AIControl` root. Never bundle classic Windows executables—accept only Microsoft-signed local or mounted sources.
- **Autostart is a logon Scheduled Task now (E12, 2026-06):** `autostart.rs::ensure_autostart_task` (called from `App.tsx` on packaged launch) registers a logon task (`BUILTIN\Users` + `RunLevel Highest`, points at the current exe `--minimized`, idempotent, clears the legacy HKCU `Run` value). It replaces the per-user `Run` key, which couldn't auto-elevate this `requireAdministrator` app. `tauri-plugin-autostart` is still a dep but **inert** — don't call its `enable()`; use the command. The task name embeds the app display name so Lockdown's `*WinCommander*` sweep removes it.
- UI redesign U0-U4 is implemented: shell/search/panels use `useVisibility()` / `Visibility`; `useFeatureVisibility` is gone. Keep legacy `experienceLevel`/`modules` writes in sync for one release because backend module gates and old settings still read them.
- `getToggleVisibility(toggle, profiles)` needs the selected capability set. Calling it without `profiles` can classify legacy `minExperience: "standard"` rows too broadly and leak safeguards-only rows into Guided.
- `cover:"deniable"` is tied to the backend profile session via `useCoverUnlock()` (`initialize_profile_session`, `is_profile_session_unlocked`, `unlock_profile_session`, `lock_profile_session`). Never replace it with local component state; locking the profile must immediately hide those rows again.
- Bun tests use `bun:test`; the repo keeps a local TypeScript shim at `src/bun-test.d.ts` so `bun x tsc --noEmit` can type-check test files under the strict `src` include.
- To add a forbidden AV-flagging token to the Free-binary strings check, edit `tools/strings-grep-forbidden.txt` — not `tools/strings-grep-free.ps1`. A new token fails the local `bun run lint:strings-free` (`-HardGate`, exit 1) and the CI `strings-grep-free` job, which runs the same scan as a **blocking** gate.
- Tauri release builds embed Rust strings and Vite assets into `wincommander-free.exe`. For Pro/destructive IPC IDs that Free must still recognize, use `command_strings.rs` (Rust) or `src/lib/commandIds.ts` (frontend) instead of contiguous command-name literals.
- **Context-menu verbs route by flag; a missing branch SECURE-DELETES the target.** Right-click verbs launch the exe with a flag (`--scrub`, `--safe-copy`, `--safe-paste`), and the arg dispatcher's DEFAULT is `shred-requested`. Both `session_instance.rs::handle_forwarded_args` (running instance) AND the `lib.rs` `setup()` cold-start emission (app was closed) choose the event; a flag missing a branch in EITHER falls through to shred. When you add a verb, add its branch to BOTH or the folder/file the user picked gets 7-pass wiped. **Safe Copy / Safe Paste** (`safe_clip.rs`): Safe Copy is HEADLESS — handled at the top of `run()` BEFORE the single-instance guard (so it records + exits, never forwarded/windowed); Safe Paste copies sources into the target folder keeping the EXACT name (collision → skip, NEVER renamed; nested decoys skipped via `copy_tree`'s `skip` predicate; no copy-into-self) then the frontend scrubs the copies in place. `safe_paste_prepare` is `require_paid` BEFORE any file op (scrub is Pro). Verbs register via `backend::toggle_safe_copy_context_menu` (reg.exe, mirrors scrub), unregister in Hidden mode (`apply_wincommander_hide_mode`) + are swept by `lockdown_impl`; `reregister_context_menus_if_enabled` heals labels on startup. Setting `app.safeCopyContextMenuEnabled`. - **CLI risk grading is registry-first, and a command's name is the last word, not the first (2026-08-03):** `cli.rs::classify_risk` decides which confirmation token `run` demands, and it used to guess purely from the command name. Consequences for anyone adding a command: registering it in `authz::DESTRUCTIVE_COMMANDS` is now sufficient to make the CLI demand `DESTROY:` — you do not also need a scary name; and if you add a handler whose name misreports its effect, put it in `RISK_OVERRIDES` with a comment saying what the body actually does, because the tests assert every override still resolves. Over-classifying is the safe direction and three erase-*scheduling* commands are knowingly caught by (4).
